# Shopify Checkout AI

Проект для анализа брошенных корзин и checkout'ов Shopify и формирования
рекомендаций администратору.

Предполагаемые задачи:

- анализ брошенных checkout'ов;
- выявление причин незавершённой покупки;
- поиск закономерностей остановки в воронке;
- выявление технических и коммерческих сигналов;
- формирование рекомендаций администратору.

## Структура

- `src/` — основной код приложения и модели;
- `data/raw/` — исходные локальные данные (не добавляются в Git);
- `data/processed/` — подготовленные данные (не добавляются в Git);
- `models/` — сохранённые модели и артефакты;
- `tests/` — автоматические тесты;
- `docs/` — документация и проектные решения.

## Важно

Checkout-данные могут содержать персональную информацию покупателей. Перед
обучением модели их необходимо минимизировать, обезличить и хранить безопасно.

## Синтетический датасет

Генератор создаёт Shopify-подобные Web Pixel и Admin GraphQL данные, а также
плоские выборки для обучения без реальных персональных данных:

```bash
python3 src/generate_synthetic_data.py
```

По умолчанию создаётся 10 000 воспроизводимых сценариев. Результаты находятся в
`data/raw/*.jsonl` и `data/processed/*.csv`. Клиенты разделены между train,
validation и test без пересечений. Описание форматов находится в
`docs/data_contract.md`.

Проверка генератора:

```bash
python3 -m unittest discover -s tests -v
```

## Базовый рекомендательный движок

Прозрачные правила анализируют тестовую выборку без чтения готовых колонок
`detected_pattern` и `recommended_action`:

```bash
python3 src/recommendation_engine.py
```

Результат сохраняется в `data/processed/recommendations.jsonl`. Каждая запись
содержит закономерность, действие, уверенность, основания, альтернативу и
запрещённое действие, если оно применимо.

## TensorFlow-модель

Установка и обучение:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python src/train_tensorflow.py
```

Модель сохраняется в `models/abandonment_pattern_model.keras`, её схема — в
`models/metadata.json`, а метрики — в `models/evaluation.json`.

Получить рекомендацию для одного случая:

```bash
.venv/bin/python src/predict_recommendation.py --case-id case-0000004
```

Для собственного подготовленного объекта можно передать JSON через `--input`.
Критические правила безопасности — завершённый заказ, явные ошибки Shopify и
остановка чрезмерных сообщений — имеют приоритет над результатом ML.

## Локальная административная страница

```bash
.venv/bin/uvicorn src.web_app:app --reload
```

После запуска интерфейс доступен по адресу `http://127.0.0.1:8000`, проверка
состояния — `/api/health`, рекомендации — `/api/recommendations/{case_id}`.

Для реальных тестовых checkout панель использует `/api/real-cases` и
`/api/real-recommendations/{case_id}`. Администратор может зафиксировать принятое
действие и позднее отметить результат как `recovered` или `not_recovered`.
Обезличенная история сохраняется в
`data/processed/checkout_interventions.jsonl` и предназначена для последующего
обучения модели выбора воздействия.

Эндпоинт `/api/outcome-analytics` объединяет checkout и последнее применённое
воздействие, автоматически распознаёт восстановленный Shopify-заказ и считает
recovery rate по каждому типу действия. Незавершённые наблюдения остаются в
статусе `pending` и не искажают процент эффективности.
